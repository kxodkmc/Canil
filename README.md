# 简历工作室 · Resume Studio

浏览器内的结构化简历编辑器：内容与排版彻底分离，改内容不跑版，拖拽即排序，一键压进一页，导出即印即用。前端零框架，后端 FastAPI + SQLite，支持多版本与投递记录管理。

## 为什么不用 Word 写简历

| Word 的痛点 | Resume Studio 的解法 |
|---|---|
| 调格式半小时，多写一行就跑版 | 内容存数据、排版走模板，字号/行距/间距滑杆实时生效；**「自动适配 1 页」按视觉影响从小到大逐级收缩，超页自动压回一页** |
| 从网页/AI 复制内容，样式粘得到处都是 | 粘贴强制转纯文本，样式与内容物理隔离，永远不会被带入脏样式 |
| 挪个模块要剪切粘贴半屏 | 模块与条目**拖拽即排序**，右侧 A4 预览实时跟随 |
| 投不同岗位要维护 N 份文件 | **多版本管理**：一份数据派生多版本，各带独立排版与投递记录 |
| 投了哪些岗位、用的哪版简历，全靠回忆 | **投递总览**：跨版本汇总、日期倒序、近 7/30 天统计，点版本名直接跳转对应简历 |
| 排版好看的模板要付费 | 内置两套模板（经典极简 / 商务蓝），主题色一键换 |

## 功能

**编辑**
- 左侧结构化编辑器 + 右侧 A4 实时预览，**双向同步**：编辑器输入不重建 DOM、不丢焦点；预览文字可直接点击修改（所见即所得）
- 模块/条目拖拽排序、折叠收起；内容超页实时告警（页数徽标 + 1/1.5 页边界虚线）

**模板与打印**
- 两套模板独立样式文件，主题色驱动，互不干扰
- 导出 PDF 走浏览器原打印管线：`@page` 锁定 A4 无边距，打印前自动重置缩放，背景色 `print-color-adjust` 双保险（background + inset box-shadow）

**数据**
- 多版本（另存为/重命名/删除）、JSON 备份导入导出、投递记录随版本走
- **AI 协作**：一键复制标准化提示词喂给任意 LLM；AI 返回的 HTML 经 `<resume-data>` 格式校验后导入，非法内容拦截，绝不污染当前编辑

**云端**
- 邮箱白名单注册 + JWT 会话；数据实时同步云端，编辑器折叠态等纯 UI 状态不入库
- 管理后台：注册白名单与用户管理

## 架构

```
JL/
├── resume-studio/          # 前端（后端静态托管，前后端同源）
│   ├── index.html / admin.html
│   ├── css/                # base / layout / editor / resume / resume-t2 / modal / auth
│   ├── js/                 # 16 个模块，window.RS.* 命名空间
│   │   ├── rs.js util.js       # 命名空间与工具
│   │   ├── model.js store.js   # 数据模型与唯一状态持有者
│   │   ├── api.js auth.js      # REST 客户端与会话
│   │   ├── editor.js preview.js# 双栏编辑/渲染核心
│   │   ├── versions.js apps.js # 版本管理与投递记录
│   │   └── ...                 # 样式面板 / AI 导入 / 工具栏 / 拖拽宽度
│   ├── fonts/              # OPPO Sans 4.0
│   └── test/smoke.js       # jsdom 冒烟测试（58 条断言）
└── backend/                # FastAPI + Tortoise ORM + SQLite
    └── app/
        ├── api/v1/         # auth / resumes / me / admin
        ├── core/           # 配置、安全(JWT+Argon2)、限流、错误处理
        └── services/       # 业务逻辑
```

**关键设计决策**

- **前端零运行时依赖**：16 个职责单一的模块构成，加载即用，无构建步骤、无框架税；复杂度集中在状态层（`store.js` 是唯一可变状态的持有者），视图层全部单向渲染
- **内容与样式分离**：`resume-data` 数据结构不含任何表现信息，一套数据可在两套模板间任意切换；这是「粘贴不乱」的根因
- **自适应一页是确定性算法**：按「模块间距 → 条目间距 → 行距 → 字号 → 页边距」的视觉影响顺序逐级收缩并设下限，结果可手动复现，不依赖魔法数
- **UI 状态与业务数据分治**：模块折叠等纯界面状态只存内存——既不污染云端数据，也不会被保存冲突回滚重置
- **并发安全**：简历版本带 `revision` 乐观锁，409 冲突时提供「覆盖 / 拉取」二选一；登录态过期统一拦截
- **可测试**：冒烟测试用 jsdom 真实加载全部脚本并 mock 云端 API，覆盖登录、编辑、所见即所得、版本操作、AI 导入拦截、模板切换、投递总览等 58 条断言

## 安全

- 密码 Argon2 哈希；JWT HttpOnly 会话
- 注册邮箱白名单（管理后台维护），默认关闭开放注册
- 登录/注册接口限流；请求体大小上限校验
- 前端所有用户内容经 HTML 转义渲染，AI 导入走白名单标签解析

## 快速开始

依赖：Python 3.12+ 与 [uv](https://docs.astral.sh/uv/)、Node.js（仅跑测试用）

```bash
# 启动（后端同源托管前端）
cd backend
uv sync
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8300
# 打开 http://127.0.0.1:8300
```

```bash
# 冒烟测试（无需后端，jsdom 内置 mock 云端）
cd resume-studio
npm install        # 仅 jsdom
node test/smoke.js
```

单文件版 `简历工作室.html` 可直接双击打开（本地存储模式，无需后端）。

## 账号与白名单

- 管理员由 `backend/.env` 的 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 引导创建（启动时幂等执行），登录后工具栏出现「管理」入口
- 注册采用邮箱白名单：管理员在后台添加允许的邮箱，仅名单内邮箱可注册
